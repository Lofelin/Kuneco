# Git 管理

设置 → 工具 → Git 管理提供提交身份、SSH 密钥、连接检测和 HTTPS 凭据。浏览器设置同属工具分组。

## 配置范围

- 受管容器使用持久化 home 卷下的 `.config/kuneco-git`；管理配置通过 include 纳入该容器的 `.gitconfig`。控制台和容器运行时执行 Git 时使用相同配置。
- 本机环境在应用数据目录 `git-environments/<账号哈希>` 保存独立配置及密钥。Kuneco 启动的本机运行时通过 `GIT_CONFIG_GLOBAL` 使用此配置，不修改宿主全局 `.gitconfig` 或默认 SSH 密钥。应用外启动的终端不会自动继承。
- 已有容器在该容器用户 home 下配置。其网络使用原容器网络及代理环境变量，不声称受到受管容器的隔离规则保护。
- 提交身份可保存为环境默认值，或为当前已选择的 Git 项目设置环境内覆盖。项目覆盖存于当前环境目录，以 gitdir 条件应用，不修改共享仓库的 `.git/config`，因此同一仓库挂载到不同环境也不会串用。仓库自身显式设置仍优先生效。未选择 Git 仓库时，仓库范围不可用。

## 密钥和凭据

新建密钥生成独立 Ed25519 文件并切换使用，不覆盖旧密钥。下拉可切换具有私钥的已有密钥；显示公钥指纹，不回传私钥。无选定密钥时禁止使用默认宿主密钥或 SSH agent 中的其他身份。

HTTPS Token 通过 stdin 传递，仅保存于对应环境权限 0600 的 `credentials.json`。凭据助手按 HTTPS 域名及端口精确匹配，页面仅回显域名与用户名。移除平台配置会删除该条凭据。此文件不是加密保险箱；它与该环境内其他开发凭据一样由环境文件权限保护。

## 实际网络检测

- 受管容器在所选容器内读取 `/tmp/dingtu-chat-proxy` 中最新代理地址，不使用可能过期的创建时 token，不回退直连。
- 本机环境通过当前应用代理，并由现有网络沙箱限制为只连接当前网关。代理未连接或未核验时拒绝检测。
- 已有容器在原容器内执行，继承其 HTTPS/ALL_PROXY 设置；无代理时使用原容器直接网络。
- SSH 通过 HTTP CONNECT 或 SOCKS5 桥接，目标域名交由代理解析。HTTPS 使用 Git `ls-remote`，Token 不进入 URL 或命令参数。

`ssh://git@github.com` 检测 SSH 认证；完整 SSH/HTTPS 仓库地址检测读取权限，不测试写入权限、不推送代码。GitHub/GitLab 的 SSH 成功提示可对应非零退出码，界面按认证结果判定。自建平台无法识别认证提示时可改用完整仓库地址检测。

首次 SSH 连接默认不信任未知主机。用户勾选首次信任后使用 `accept-new`，保存到独立 known_hosts；已记录主机密钥发生变化时仍拒绝连接。未知主机或密钥变化、认证失败、仓库不存在/无权限、网络超时分别显示；服务器隐藏权限导致的 404 不强行细分。
