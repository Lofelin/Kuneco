# 容器网络隔离

Kuneco 管理的环境使用两条明确的执行路径。第三方关联容器不宣称具有同样的防火墙保障。

- 代理任务始终运行在工作容器，只接入当前环境的内部私有网络。IPv4 / IPv6 OUTPUT 默认拒绝；IPv4 仅放行当前网关的 TCP 8080 和本容器回环通信。
- DNS 在 raw OUTPUT（地址转换前）阻断 TCP / UDP 53；Docker DNS 专用地址 127.0.0.11 的全部端口也被阻断，不能借助其高位解析端口绕过。IPv6 同样阻断直连 DNS。
- 显式直连任务按次启动独立、自动清理的执行容器，使用账号/环境派生的专属出口网络。它不为代理工作容器增加网络接口、GID 放行或 DNS 中继。执行容器非 root、无额外 capabilities、只读根目录，并沿用进程、内存和 CPU 限额。
- 同环境共享 home、workspace 以及用户配置的项目挂载，以保留登录、运行时和工作文件。网络、PID 和 `/tmp` 不共享；需要跨次保留的文件应放在 workspace 或 home。取消会等待容器创建边界，并按确认归属的容器 ID 停止/清理，避免遗留任务。

## 边界

这是网络出口隔离，不是同环境恶意代码之间的完整安全沙箱。共享可写文件、登录配置及 Unix socket 路径仍属于同一信任域；不能保证一个获准直连的恶意任务不会通过共享数据协助另一个任务。需要运行彼此不信任的任务时，应使用不同环境及不同挂载，不共享账号凭据。主机 Docker 管理权限也能改变规则，不能作为被隔离的普通任务权限。

固定出口核验、服务探测与转发状态继续独立；原生代理保持默认，GOST 仍需显式启用。没有静默直连或副作用请求自动重放。健康 CONNECT 没有总时长限制。

## 检查与迁移

启动/复用会检查完整规则、顺序以及工作容器网络；旧共享直连规格会通过工作镜像升级替换，保留原数据卷，升级失败保留回退路径。不修改账号数据。环境主内容展示按需读取的防火墙、私有网络、DNS 和直连任务状态；读取失败、停止及外部容器不会显示“核验通过”。页面读取不会重启或断开代理。

## 验收

- `node --test test/unit/environments/*.test.mjs`
- `node test/integration/test-container-firewall.mjs`
- `node test/integration/test-container-reliability.mjs`

集成测试仅创建带唯一前缀的测试容器/网络/数据卷，并在完成后清理这些资源；覆盖指定网关、被禁目标、直连可用、DNS/IPv6 拦截、规则缺失、非特权修改失败、启动即取消、升级回退和数据卷保留。
