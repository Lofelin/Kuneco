# 容器可靠性

托管 worker、gateway 和临时 installer 使用 Docker `--init` 回收孤儿进程，日志采用 `local` 驱动，单文件 10 MiB、保留 3 个。worker 的根目录只读、权限与网络规则、CPU/内存/PID 上限保持原值；gateway 不精简镜像、不改默认代理内核。

任务取消先写本任务取消标记，再向执行包装进程发送 TERM。包装进程终止所属任务进程组，最多等待 1 秒后 KILL 残余进程，避免主进程先退出留下后代。正常结束无后代时不增加等待。不重放任务。

worker 自检确认网络初始化完成标记；gateway 自检只访问容器内控制入口。自检不访问出口检测服务，不自动重启容器，也不代表代理已核验或所有运行时已登录。环境列表显示初始化、自检失败、OOM、异常退出及状态读取失败；代理核验仍由独立代理状态展示。停止失败不再吞掉错误。

规格更新只在当前启动/连接流程内执行，不扫描迁移其他账号或未选中的容器。worker 镜像在用户选定基础镜像上覆盖执行入口，按基础镜像 ID 和源码内容生成标签；不更新用户安装在 home 卷内的运行时。规格指纹覆盖镜像、私有网络、网关地址及项目挂载。

升级先构建，再停止旧容器并保留为备份；新容器沿用完全相同的 home/work 卷和配置中的项目挂载，通过本地就绪检查后才删除旧容器本体，不使用 `rm -v`。失败恢复旧名称和原运行状态；若操作已因切换/停止取消，不启动过期环境。网关保留私网地址，控制服务就绪后才删备份。原容器挂载不匹配时停止自动升级，保留数据供人工核对。相同规格重连不重建 worker，也不丢失临时状态。

不设置 `restart: always`，不根据外部探测失败重启，不自动恢复副作用任务；固定出口、隔离和禁止静默直连保持不变。

验收：`node --test test/unit/environments/*.test.mjs`；隔离 Docker 验收 `node test/integration/test-container-reliability.mjs`（创建仅本测试的容器、网络和数据卷，验证保留、回退、init 回收后清理）。实际账号数据卷不用于故障注入。

边界保护：worker 的必需挂载与额外挂载双向核对，相同规格复用也不跳过检查；无法读取现有容器状态时，先通过容器列表确认是否确实不存在，无法确认则停止操作。同一环境的网关准备按顺序执行，失败释放队列。网关构建使用已核验的基础镜像 ID，避免镜像标签变化导致缓存指纹与实际构建内容不一致。

隔离复核：启动前确认私有网络仍为本应用的 internal bridge；复用 worker 默认只允许当前私网；显式直连功能附加 bridge 时，必须复核 IPv4/IPv6 的 OUTPUT DROP 及仅允许直连 GID 1001、回环和指定代理网关的规则。网关只允许当前私网与 bridge。发现额外网络或网关持久挂载时保留原容器并报错，不擅自断开网络或丢弃挂载。升级创建携带一次性标识，失败清理先核对该标识，再按容器 ID 删除；同名冲突或归属不明时保留容器和备份，不按名称强删。

直连 DNS TCP 转发在任一端关闭、出错或空闲超时后同时释放两端连接，不重试请求。停止状态的 worker 启动就绪后也执行网络和直连防火墙复核。
