# Kuneco

Kuneco is a unified workspace for isolated environments, containers, and proxy management, built toward seamless collaboration between AI agents across platforms.

这是一个 macOS 上已启动并完成模拟网络验收的桌面原型。用户提供代理，内置 Chromium 浏览器与本机 Claude Code 的模型请求共用应用生成的本地代理入口。

**当前仅为应用代理模式：没有系统级网络守卫，不能宣称“所有流量禁止直连”，也不能保证账号免封。** 浏览器已禁止目标域名的本机 DNS 解析，上游主机必须填写 IP；其他程序与未知子进程的联网仍需系统级隔离才能作严格保证。

## 启动

需要 Node.js、npm，以及已安装的官方 Claude Code CLI。首次安装依赖需要正常联网。

```bash
git clone https://github.com/Lofelin/Kuneco.git
cd Kuneco
npm ci
npm start
```

本机 CC 检测顺序为启动应用时的 PATH，以及 `~/.local/bin/claude`。本次验证的本机 CLI 为 2.1.232，SDK 固定为 0.3.232。其他版本需重新做兼容验证。

## 使用

1. 在「出口与连接」填写代理，或使用「IPRoyal 一键导入」「导入 TXT / CSV」「粘贴内容」。单条自动填写，多条需选择一条；没有协议的 IPRoyal 导出默认使用 HTTP / HTTPS，SOCKS5 可在粘贴窗口选择或导入后调整。这里输入网络代理，不是模型 API 地址。
2. 点击「连接并核验出口」。应用通过代理使用 ipify 和 AWS checkip 核验；失败暂停转发并自动重试。首次出口按代理配置持久化绑定，后续重连不能自动接受其他 IP。
3. 「工作浏览器」默认使用 Google：输入关键词后点击访问或按回车进行搜索；输入 HTTP／HTTPS 网址或域名则直接访问。空输入打开 Google 首页；代理已就绪时，新建标签会自动访问 Google 首页。地址栏下拉展示当前输入的搜索入口、应用内浏览历史和已打开标签，支持方向键、回车、Esc 和鼠标选择，历史保存在本机。网页与搜索继续共用配置的代理，不会自动打开网页或自动登录。
4. 「本机 CC」选择项目目录，使用已有官方登录发送需求。应用展示回复，文件修改需要确认。
5. 点击「断开」停止应用代理、浏览器连接和当前 CC 请求。

不提供代理购买、账号代注册、订阅代付或共享账号。没有替用户登录、充值或调用模型做验收。

## IPRoyal 导入

- 控制台「Copy list」复制列表后，点击「IPRoyal 一键导入」从剪贴板读取。
- 点击「导入 TXT / CSV」选择本地导出文件，或点击「粘贴内容」手动粘贴。
- 支持实际导出 TXT 的 `host:port:user:password` 和 CSV 的 `Host,Port,User,Pass` 表头。
- 兼容 `host:port@user:password`、`user:password@host:port`、带协议代理 URL，以及无凭据的 `host:port` 白名单格式。
- 多条列表只用于选择固定入口，不自动轮换；候选列表不展示用户名或密码。
- IPRoyal 的 `HTTP|HTTPS` 在应用中对应 **HTTP / HTTPS**：通过 HTTP 代理入口转发 HTTP 网站，访问 HTTPS 网站时建立 CONNECT 隧道并验证目标证书。**HTTPS（TLS 入口）** 仅表示到代理服务器的连接本身也使用 TLS，不能因为目标网站是 HTTPS 就选择它。剪贴板和文件导入默认使用 HTTP / HTTPS，不继承之前误选的 TLS 入口；粘贴窗口可明确选择 SOCKS5。带协议 URL 保留其显式协议。
- 新增代理弹窗分为「手动填写」「导入文件」「粘贴内容」三种互斥方式，分别显示表单、文件选择和文本解析区域。文件选择直接嵌入导入区，包含路径栏、上一级、访问目录及固定高度内部滚动的文件列表，不再叠加文件选择弹窗；底部统一“取消 / 导入并解析”，解析完成再显示“保存并连接”。导入解析后显示所选代理摘要，多条需选一条；不再嵌套导入弹窗。导入只生成草稿，不覆盖配置或断开现有连接；用户点击「连接并核验出口」后才提交新配置并连接。
- 一次最多 500 条、1 MB。CSV 支持 BOM、引号、逗号、转义双引号和 CRLF；错误显示行号，不回显原始凭据。
- 住宅网关或会话参数会提示核实是否轮换；导入不会改变供应商的出口分配行为。

已使用用户提供的 TXT 与 CSV 验证解析配置一致，未把真实凭据复制到代码、测试样例或截图。后续代理故障排查中，已用用户提供的上游分别访问 HTTP 与 HTTPS 出口检测服务，两者成功且出口一致；未登录或调用 Claude。

参考：[IPRoyal ISP 导出说明](https://iproyal.com/quick-start-guides/static-residential-proxies/)。

## 已实现

- 中文桌面界面：出口与连接、工作浏览器、本机 CC。
- IPRoyal 剪贴板、TXT／CSV 文件和粘贴导入，支持多条代理选择。
- HTTP／HTTPS 上游 CONNECT 隧道、SOCKS5 上游认证和代理端目标域名解析。
- 仅监听本机回环地址的本地代理入口，并带随机认证凭据。
- HTTP 请求与 HTTPS CONNECT 都通过指定上游发送，不配置备用出口或直连兜底。
- 连接前阻断，出口核验失败阻断，上游握手异常时锁定入口。
- 常态约每 30～36 秒核验，故障以 1、2、4 秒等退避重试（最长 60 秒）。同一出口才恢复，IP 变化或认证／TLS 安全错误保持隔离。
- 固定 IP 使用原子文件持久化，手动断开、重新连接和应用重启不清除绑定。核验超过 90 秒则禁止新请求。系统在线事件和休眠恢复触发核验。
- 浏览器禁用 QUIC 和非代理 WebRTC UDP；这些设置不是系统级防火墙。
- 核心停止时销毁活动连接和正在握手的连接。
- 浏览器独立持久会话、前进后退、刷新、下载；支持多标签新建、切换和关闭；网页新窗口链接在新标签中打开。
- 官方 SDK 调用本机 CC，流式回复、会话恢复、新会话、取消请求与单次文件编辑授权。
- CC 开放 Read、Glob、Grep、Edit、Write、WebSearch、WebFetch；文件编辑需确认，网页搜索与读取可直接使用；Shell、MCP 和子代理保持禁用。
- 不加载用户／项目的 CC 设置、插件和 MCP，不写用户的原有 CC 配置。项目 CLAUDE.md 与自定义工具尚未接入。
- 可选择保存配置；代理密码使用 Electron safeStorage 对接系统凭据加密，不记录在连接日志中。请求失败日志只保留目标主机与端口、受控错误码和代理返回的状态码，不记录完整 URL 或原始异常。取消保存会删除之前保存的代理配置。

## 下一阶段

先实现并验证系统级网络守卫：代理进程退出后仍保持阻断；故意清除代理变量的子进程无法直接联网；覆盖 DNS、IPv6、UDP 和休眠恢复。通过这些验收后，才能开放 Shell／MCP，并把产品状态提升为严格保护模式。随后接入 Mihomo、订阅管理和受保护的官方登录流程。

目标隧道被上游以 403/404/502/503/504 拒绝时，仅该请求失败，继续通过原有代理处理其他请求；认证失败、入口故障或出口核验失败暂停转发并自动恢复；认证、TLS 安全错误或出口变化保持锁定。所有失败路径均不回退直连。连接数更新不会重复打印出口验证成功记录。

## 自动恢复验收

`node test/live-recovery.mjs /path/to/iproyal-proxies.txt` 是显式真实网络验收：通过临时 TCP 入口转发用户现有代理，在独立 Electron 进程中故意断开入口三次，验证浏览器阻断与同 IP 自动恢复，并重启验证固定出口记录。不会改系统网络、不保存代理密码、不调用模型。报告位于 artifacts/live-recovery.json。

恢复只恢复网络转发，不自动重放 CC 提示、登录表单、支付或文件操作。用户主动断开后不会自动重连。出口绑定文件损坏或无法写入时锁定，不能悄悄重建为新的 IP。健康核验是周期性的；上游若在核验间隔内换出口，应用不能承诺零窗口检测。长期稳定性仍需跨天运行统计。

## 浏览器语言与字体策略

使用 npm start 启动以应用进程独立的英文语言参数运行，浏览器默认en-US，Google首页/搜索默认英文，应用面板仍中文。没有修改macOS全局语言。浏览器配置字体访问限制并禁止本地字体枚举；常见中文字体的Canvas测量使用允许字体回退，FontFace本地加载被拒绝。系统字体没有删除。

已覆盖同源、跨域（独立进程）和 srcdoc iframe，以及 classic/module 独立 worker、嵌套 worker、classic/module 共享 worker、Service Worker 的首次脚本执行。Canvas/OffscreenCanvas、FontFace、FontFaceSet 使用同一允许列表；网页使用 Arial 用户样式。共享 worker 通过 blob 启动策略，网站 CSP 不允许 blob 时会失败，不回退到原始脚本；共享 worker 的 location 为 blob 地址，跨标签共享语义和依赖原始 location 的脚本可能不兼容。

此策略仍是浏览器 API/样式限制，不是底层字体沙箱。中文字符可能使用系统后备字体，不能保证所有恶意探测方式都无法绕过。系统字体没有删除。具体验收见 artifacts/browser-privacy-acceptance.md。

## WebRTC 与 DNS 防护

每个应用标签设置 Chromium disable_non_proxied_udp，网页层禁用 RTCPeerConnection 和 WebTransport，因此依赖 WebRTC 的通话/数据通道无法使用。关闭 QUIC。隐私策略附加异常或初始化超时会锁定代理访问；正常关闭标签不触发全局锁定。

Chromium resolver 对目标域名返回不可解析，禁用 DNS 预取和内建/安全 DNS。网页 HTTP/HTTPS/WebSocket 使用本地代理，目标域名由 HTTP CONNECT 或 SOCKS5 上游解析。为避免 Node 为上游入口进行本机 DNS 解析，配置的上游 host 必须为 IP 字面值（IPRoyal 导出 IP 可直接使用）；不接受域名入口，不改变系统 DNS。不将 DNS 地理位置与账号封禁之间的关系作为已证实事实，也不保证账号免封。

## 启动系统环境门禁

macOS 启动时读取真实全局 AppleLanguages 和新进程 Intl.DateTimeFormat 系统时区（忽略 TZ 覆盖另读一次，并与 CC 将继承的进程时区比对）。不使用应用强制英文后的 navigator.language 判断系统语言。只检查首位系统语言：首位 zh 即阻止，en-US、zh-Hans-US 等英文首位组合放行。

时区通过随应用保存的 IANA tzdb 国家映射，与 2026-10-13 核对的 Anthropic 官方支持国家/地区名单比对。UTC/Etc/GMT 等无法确定国家的时区、非支持地区、读取错误或 TZ 覆盖不一致均阻止；不是按 UTC 时差判断。地区名单来源 https://www.anthropic.com/supported-countries；官方没有支持时区名单，这只是用户指定的本地门禁，不能确认真实所在地、实体资格、乌克兰同一时区内的地域例外，或保证账号可用。名单需随官方政策变化重新人工核对更新。

门禁在主进程执行，启动默认关闭；重新检测可重复执行，不保存永久通过标志。连接代理、浏览器操作、CC 请求前重新检测，运行中每 30 秒重新检测；不通过就停止 CC、销毁代理连接并关闭转发。通过后仍须手动连接代理，不自动恢复被环境门禁关闭的会话。界面只能重新检测，不能跳过或伪造通过；仅 --test-fixture 验收进程允许虚拟环境样本。当前其他操作系统未实现原生语言读取，会保持阻止。

应用网页、iframe 和 worker 的全部 RTC 全局入口与 WebTransport 被移除并设为不可改写；媒体采集被拒绝。Chromium 库本身仍包含 WebRTC，未重新编译 Electron；隔离的开发验收世界验证原生 API 无 ICE 候选与非代理 STUN 数据包，但不是系统级网络防火墙。

## 本机 CC 的通用保护

本应用启动的本机 CC 与浏览器共用系统环境门禁。选择代理模式时执行出口核验并使用应用代理及固定 IP 记录；浏览器模式由设置选择，对话模式在新建时选择。CC 进程通过 macOS sandbox-exec/Seatbelt 创建：只允许 TCP 到应用的本地代理端口，阻止其余网络、UDP 和系统 mDNSResponder DNS 服务访问；子进程继承该约束。启动隔离失败不回退到普通进程。目前其它操作系统未实现此守卫，CC 不启动。macOS sandbox-exec 为系统现有的旧接口，未来系统兼容性需要重新验证。

CC 使用 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY 指向同一个入口，NO_PROXY 为空；LANG/LC_ALL 为英文。没有伪造系统时区。环境门禁失败、网关失败或应用停止时取消 CC 并关闭转发，自动恢复不自动重放提示。已开放网页搜索与读取，Shell/MCP 仍禁用。字体、网页 WebRTC API 和 Chromium 设置只作用于浏览器，CC 通过进程网络规则阻止 UDP/DNS/直连，不是靠给 CC 设置浏览器开关。

这个约束只作用于本应用创建的 CC 及其子进程，终端或其它应用自行启动的 CC 不受此守卫保护。已验证真实 CC 初始化握手和隔离内的网络探测，没有使用真实账号调用模型或消耗额度。

出口 IP 来自经上游代理访问 api.ipify.org / checkip.amazonaws.com 的真实响应，不从代理入口地址推导，也没有固定为198.143.6.22。首次成功后按代理身份持久化绑定；后续结果不同则隔离。UI 与浏览器验收展示该检测值，本次入口与出口相同只是观测结果。

## 本机 Codex

“本机 AI”页面可选择 Claude Code 或 Codex。检测本机 codex CLI（PATH 与 ~/.local/bin），沿用已有本机登录；通过 codex exec --json --ignore-user-config 获取分段回复，保留独立线程ID并通过 exec resume 继续。可新建会话或停止；运行中不能切换工具，切换后各自保留当前界面的对话记录。

Codex 当前为只读对话模式，可分析粘贴代码；启用实时网页搜索（web_search="live"），禁用 Shell、浏览器操作、MCP、插件、hooks 和子代理，不提供自动项目扫描或文件修改。全局用户模型/工具配置不加载，身份凭据仍由CLI原有登录管理，不复制凭据、不修改全局配置。本机不同版本需支持 --ignore-user-config、--json 与当前事件格式。协议依据 https://developers.openai.com/codex/noninteractive 和本机 codex-cli 0.142.5 帮助。

Codex 使用与 CC 同样的环境门禁、代理环境及 macOS Seatbelt 网络守卫。仅可 TCP 到本地网关；DNS/UDP/其它直连拒绝，网关失效取消并不自动重放提示。当前仅保护应用启动的CLI进程。验收覆盖真实CLI参数兼容、app-server 初始化握手、JSON事件/错误/取消与UI工具切换；未调用真实模型验证账号额度或首条回复。

打开“本机 AI”、切换 CC/Codex 时自动调用本机 CLI 登录态命令（Claude auth status --json / Codex login status），也可点击“重新检测登录态”。检测中、未登录、未安装或状态不确定时禁止发送；主进程发送前再检测。命令在相同网络隔离下执行，不自动登录，不返回邮箱/密钥/原始输出。这里只证明 CLI 本地登录状态，不代表服务端 token、账号权限或额度验证。

### Docker 环境（macOS）

左侧顶部的环境菜单提供「本机环境」与当前账号的 Docker 环境；「管理环境」可创建、启动、停止和切换环境。首次使用点「初始化引擎」，等待运行时镜像准备完成。Docker 数据在专用 `dingtu` Colima 配置下，不切换系统默认 Docker context。

使用顺序：创建环境 → 启动 → 切换 → 设置独立代理并连接 → 手动检测运行时 → 在运行时页安装和登录 Claude / Codex → 新建对话。登录信息仅进入该环境的数据卷，不自动复制宿主机登录。每个环境最多持久保留 10 个记录；停止不会删除工作文件。

每个环境由代理网关容器和工作容器组成，二者连接专属 internal 网络。工作进程使用非 root UID、零有效 capabilities、只读根文件系统和独立 `/home/node`、`/workspace` 数据卷。启动时设置防火墙，只允许访问该环境代理的 IP:8080，并禁止直接 DNS 和 IPv6 外联。没有 Docker socket 或用户主目录挂载。停止代理会关闭已有隧道，无直连回退。

浏览器仍由 Electron 显示；不同 Docker 环境使用独立 Chromium partition，网络通过环境的容器代理。浏览器进程本身尚未移入容器。容器项目当前固定在 `/workspace`，暂不提供宿主项目目录挂载。模型请求须由用户在容器内完成官方登录后验证，测试不会冒用本机登录或自动消耗模型额度。

引擎分发资源用 `npm run bundle:engine` 在构建机器准备，生成 `vendor/container-engine`（平台相关产物，不入源码版本控制）。资源包含 Docker CLI、Colima 与 Lima；发布 Electron 安装包时将此目录放到 resources/container-engine，最终安装包签名/公证仍需发布流程。当前开发版已准备本机资源。没有预装 Docker 的用户可以使用随包引擎；如果资源缺失但已有 Homebrew，开发版初始化可下载安装依赖。没有内置资源且没有 Homebrew 时明确提示缺少完整组件，不执行不受控安装脚本。

`npm run test:docker` 使用临时环境和临时代理验证容器运行、无直连/DNS、数据持久化、进程取消、HTTPS 经代理及断线阻断，并清理自己创建的容器与数据卷。不会使用用户代理凭据或调用模型。

## 开发约束

- 运行时列表点击进入当前页内的详情页，不打开详情弹窗。详情采用主信息与右侧操作双栏，顶部返回列表，正文内部滚动；主信息包含所有者、当前环境、版本、登录状态、技术详情及真实关联对话，右侧复用配置/登录和移除操作。状态与内容必须来自当前账号和环境，不以安装成功冒充在线，不展示未实现的公开可见性或智能体能力。

- 所有弹窗四周外缘内边距统一使用 `--dialog-inset:16px`，标题、正文、底部操作左右边线对齐，顶部和底部均保留同样的 16px。内置 header/footer 与自定义标题/分区必须复用此参数，禁止各自设置 22/26/28px 造成叠加；分区式弹窗外层 body 为 0 时，内层各分区使用同一参数。内容内部的分组间距独立设置，不得通过增加弹窗外缘留白实现。标题到首段正文只保留一份 16px 间隔，禁止 header 底部、body 顶部和首段默认 margin 叠加；紧凑表单的说明与输入框间距为 12px。

- 所有带前置图标的下拉选择器，触发器选中项与展开菜单项的图标和文字起点必须分别对齐。统一触发器水平 padding 16px、菜单 padding 3px、菜单项水平 padding 12px（结合 1px 边框），图标 16px、图标到文字间距 8px；选中项与选项字号一致。紧凑控件可统一缩小字号，但不得让图标或文字左右错位。新增下拉必须展开后对照截图核验。

- 所有弹窗的确认、取消、关闭及提交按钮必须复用 `.content-action` 与主内容区右上角同一套样式：30px 高、左右 8px 内边距、12px 字号 / 18px 行高、14px 图标和 6px 图文间距，不得单独放大或新增尺寸覆盖。所有弹窗底部操作统一右对齐，取消/关闭在左，确认/提交/创建/删除在右，按钮间距 8px；DOM 顺序与视觉和键盘顺序一致，不用 CSS 倒序。返回等辅助操作放在取消之前。所有确认及取消按钮必须使用 start 插槽图标，取消/关闭用 x、常规确认用 check、删除用 trash-2，特定动作可用对应图标；图标 14px、文字间距 6px，动态修改文案只更新文字 span，不能移除图标。只有单个关闭或确认按钮时仍右对齐并带图标。新增和现有弹窗均遵循此规则。

- 页面及分区工具栏按钮统一复用主内容区右上角操作样式（`.content-action`）：30px 高度、左右 8px 内边距、12px 字号 / 18px 行高、14px 图标、图标与文字间距 6px。不要在设置分区另建一套按钮尺寸。代理“重新连接”直接使用当前配置；无配置时“新增代理”打开空白草稿表单；有配置时显示“编辑代理”并回填当前配置，未修改代理身份时密码留空沿用已保存密码。草稿不得自动覆盖当前代理，取消后丢弃草稿。

- 只读信息卡片复用 `.info-card`：标题在卡片外，卡片使用 surface 背景、1px line 边框和 12px 圆角；内部采用语义化 dl/dt/dd 两列布局，左侧灰色标签宽 140px、右侧正文自适应，列间距 24px、行间距 8px，内边距上下 20px / 左右 24px，13px 字号及 1.6 行高。窄屏标签宽 100px、列间距 16px、内边距 18px，行间距仍为 8px；长值允许换行，状态用有色圆点配合文字，不重复展示冗余说明。连接信息遵循此样式。

- 数据列表（连接记录、运行时管理、环境展开后的运行时）统一使用圆角边框表格样式，并复用 `--data-list-*` 参数：10px 圆角、1px 分隔线、表头背景 `color-mix(in srgb,var(--surface) 75%,var(--soft))`；表头上下 12px、数据行上下 10px、左右 20px 内边距，12px 字号、1.6 行高，单行高度 40px（含分隔线约 40px）。不要另设更大的 min-height 或叠加垂直 padding；长文允许换行，不截断内容。所有数据列表页面标题和操作栏都放在滚动区域外，始终可见；列表表头在所属滚动容器顶部吸顶，使用不透明背景及高于数据行的层级，不能随行内容滚出。运行时管理和连接记录在表格内部滚动，环境页正文独立滚动且运行时表头吸顶；横向滚动时表头与行保持列对齐。新增同类列表复用以上布局及参数，保持行高、表头背景和滚动行为一致。

- 浏览器 Cookie 云端同步固定按认证账号与当前环境隔离，环境键由应用内部取当前环境 ID，本机环境使用内部 local 键。设置只展示保存位置，不提供环境标识的展示、编辑或手动关联；旧配置中的自定义 environment 不参与同步选路。

- 设置子页统一由 `.settings-body` 提供标题下方 28px 的正文起始间距；首个 `.preference-heading` 的上外边距必须为 0，不叠加默认标题 margin。说明文字放在对应控件组下方，间隔 12px，并与组内文字的 20px 水平内边距对齐，不得紧贴卡片边框或混入标题空白区。新增设置子页需与现有子页对比截图验收。
- 对话创建时必须保存独立的 `networkMode`（proxy/direct/auto），历史缺省按 proxy 处理；auto 在每次发送前选择路径：已核验代理可用时优先代理，否则直连。发送后代理失效仅停止当前请求，不自动重放；下次发送重新选路。对话标题栏可手动切换，正在发送时先停止旧请求再保存新模式；需要代理的对话全程受代理门禁约束，失效立即停止且不自动直连。直连对话独立于浏览器设置，不修改原容器的隔离规则。角标叠放于对话头像左上角，不独占一行；对话项采用紧凑高度。使用绿色盾牌图标表示需要代理、蓝色地球图标表示直连，仅以悬停提示和可访问名称显示含义，状态行不重复品牌名称。新建对话的连接方式下拉选项及选中状态均显示对应的有色图标。托管 Docker 环境的直连对话用临时容器共享当前环境的 home/work 卷；退出即移除。接入的已有容器仅支持直连对话，因为应用无法为其原有网络保证全程代理隔离，代理对话拒绝启动。

- 标签的右键菜单跟随账号界面语言，固定/取消固定、关闭和关闭其他标签必须保留最后标签保护；关闭其他标签保留已固定标签。横向溢出只在固定裁剪容器内滚动，展开时不得进入一级导航区域，收起时不得覆盖顶部窗口工具按钮。

- 所有新增按钮必须配有含义明确的图标，统一使用本地 `assets/icons` 图标与组件 `slot="start"`；纯图标按钮必须提供可访问名称。一级导航主内容标题行右侧的操作按钮全部遵守此规则。更新按钮文案时只更新独立文字节点，不能用整个按钮的 `textContent` 覆盖图标；验收中检查图标资源存在且检测、重连等状态变化后仍保留。

- 一级导航的主内容页统一使用 `.content-page-header` 作为首行，紧贴内容区顶部，复用 `--content-heading-height`（当前 49px）、左右 14px 内边距、底部分隔线和 16px 标题。标题在左，页面操作在右并垂直居中。不要在页面外层增加内边距或单独覆盖标题字号；说明、状态和正文放在标题行下方的独立内容区。控制台、运行时、环境等页面均遵循此约束。
- 运行时的检测、安装和登录入口集中在「运行时」一级导航；「设置 → 设备 → 本地系统」只承载设备的系统检测。迁移入口时同步更新新建环境引导、成功弹窗和空状态文案。
- 环境列表直接展示各环境及其 Docker 容器信息，不使用全局引擎就绪卡片替代容器信息。环境切换使用顶部环境菜单。
- 除对话的会话标题外，所有主内容标题必须配有对应的本地图标；设置子页切换时同步更新图标，并只替换独立标题文字节点。空状态在标题行下方可用内容区水平、垂直居中，避免重复显示右上角已有的操作按钮。危险操作放在同组最右侧，使用红色实底及白色文字和图标。
- 修改共享布局后，验收标题行高度、左右边界、操作按钮对齐与终端可用空间，并保留现有账号归属和代理校验。

### 运行时安装弹窗与 DeepSeek

运行时页检测为 0 时在右上角显示「添加运行时」入口，已检测到工具时隐藏。两步弹窗先选择基础运行时，再配置显示名称和描述；安装命令只读展示官方 Linux 安装命令，不接受自定义可执行命令。Claude 使用[官方安装脚本](https://code.claude.com/docs/en/setup)，Codex 使用[官方 npm 安装命令](https://developers.openai.com/codex/cli/)。名称和描述保存在当前环境，并在重新检测后保留。支持 Claude Code、Codex 命令行工具，以及 DeepSeek API 接入。DeepSeek 按[官方 API](https://api-docs.deepseek.com/)使用 API Key，配置时获取 `/models`，从返回列表选择默认模型，配置失败保留原配置。安装与 API Key 配置无需先连接代理：临时下载容器通过独立网络运行，只挂载当前环境 home 卷，完成或失败后移除；对话容器原有的代理隔离规则不变。

DeepSeek 密钥通过 stdin 交给容器内适配器，不进入命令行参数或运行时元数据；配置以 0600 权限存放在当前容器 home 卷的 `.config/dingtu-deepseek`，对话历史按会话保存。对话调用官方 `/chat/completions`，不自动重试，不提供 Shell、网页搜索或文件编辑。DeepSeek 仅在应用管理的容器中配置；本机和接入的原容器保留既有的手动安装方式。测试使用模拟响应，不提交真实密钥或调用真实模型。

标签右键菜单宽度由最长文案决定，悬停背景两侧保留间距；点击菜单外部关闭，菜单内部点击仍执行对应操作。

代理设置：统一 TXT / CSV 文件导入入口，保留粘贴内容入口。配置标题位于卡片外并显示账号保存范围：本机代理随账号同步，Docker 代理按账号和当前环境保存在本机加密配置中。连接记录由主进程生成，最多保存 200 条，加密保存到当前设备的账号专属文件；重启恢复，切换账号隔离，不包含代理表单或网页正文。

环境概览以紧凑身份头、基础信息和通栏运行时列表上下排布，保留真实容器信息，不展示无来源的健康度或费用；环境主标题不显示数量。标签关闭操作悬停使用浅红背景并保留菜单两侧留边。

创建环境采用三步流程：填写名称（下一步不创建数据）、选择/配置环境类型（下一步预览运行时）、自动检测运行时（失败可重试）。第二、三步主标题右侧可返回上一步并保留草稿；最终点击创建按钮才创建环境，即使未发现运行时也可创建。创建成功后显示成功弹窗。

环境类型始终展示本机选项，已有本机环境时禁用并标注「环境已存在」。环境页删除按钮只针对当前环境，保留名称确认；删除后按切换菜单顺序选择下一项，末项删除则回到剩余首项，无环境时进入创建向导。

当前环境范围：环境主内容仅显示选中环境；对话标签与草稿按账号和环境分别保留（应用会话内），连接记录按账号加密存储、按环境过滤。旧连接记录无环境标识时保留文件但不混入当前环境列表。账号资料、语言偏好继续按账号共享；本地系统设置为设备级。自动化当前仅占位，无任务数据。

- 详情页的配置、登录、删除等页面级操作统一并排放在主内容区标题栏右上角，复用 `.content-action` 尺寸和图标间距；删除、卸载等破坏性操作必须使用红色实底及白色文字和图标。面包屑只展示实际导航层级（如“运行时 › 当前运行时”），环境名称保留在信息卡中，不插入额外导航层级。

- 删除、卸载等按钮统一使用 `variant="danger"` 通用危险操作样式：默认使用柔和红色实底（#e05252）、同色边框及白色文字和图标；悬停和键盘焦点使用较深红色（#ce4242），按下使用更深红色（#bc3535）。页面、分区、弹窗及“更多”菜单中的删除/卸载操作共用此配置，不得默认白底，也不得在交互时回退灰色或白色背景；禁用态保持不可操作及可辨识的红色危险语义，尺寸和图标间距仍复用全局操作按钮规范。

- “更多”等操作菜单按最长菜单项的图标和文字自适应宽度，不设置无必要的最小宽度或撑满触发区；统一 4px 菜单内边距、30px 菜单项最小高度、6px/8px 项内边距、12px 字号及 14px 图标/6px 图文间距。普通操作项不预留复选勾选列；账号、环境等包含信息或选择器的专用面板保留各自布局。

- **网站字体与图标兼容为全局约束**：后续调整内置浏览器字体限制、预加载脚本或注入样式，不得破坏网站正常文字、图标、布局及交互显示。禁止对全部网页元素强制覆盖字体，禁止提前替换网站自定义字体名称、图标字体、CSS 字体变量和延迟加载字体别名。
- 网页下载字体、跨域样式声明字体、动态 FontFace 字体、字体连字图标、SVG 和图片图标必须保持可用；不得出现方框、缺字、图标名称替代图形或图标消失。字体访问限制应针对本机字体访问及探测，不得以屏蔽网站正常资源代替限制；继续保留相应隐私回归。
- 每次修改字体限制，必须通过 `test/browser-font-compat.test.mjs` 及相关测试，并在重启后的内置浏览器检查实际网页：至少覆盖 Google Fonts Material Symbols（字体图标）、GitHub（SVG）、Wikipedia（图片与导航图标），同时复验本次变更涉及或曾出现问题的网站（如 Claude）。检查初次加载及延迟资源加载后的显示，不得只以构建成功或接口通过认定完成。若出现显示回归，必须修复后才能交付。
- 网站图标兼容验收记录维护在 `artifacts/browser-icon-compatibility.md`，明确已检查页面、结果及未覆盖范围，不作未经验证的全网站兼容保证。

- 窗口标题栏拖拽区域不得与后退、前进、侧栏开关及标签操作按钮重叠；不能只依赖 z-index 或 no-drag 覆盖相交的原生拖拽区域。新增拖拽层后，必须在侧栏展开、收起和窄窗口下实测按钮点击与空白区拖动。

- 重新连接、重新检测、刷新、重试等可重复操作统一添加 `.retry-action`：默认蓝色文字及图标、标准面板背景，悬停/按下/焦点使用浅蓝背景和蓝色边框，尺寸与现有内容区操作按钮一致；不得用删除红色或成功绿色。执行中使用 loading/aria-busy 状态旋转图标并由操作逻辑禁止重复提交，尊重减少动态效果设置；普通不可用状态不得误显示正在执行。

### 浏览器自动选择线路

- 自动选择优先应用代理，首次建立连接失败或代理未连接时才尝试直连，不再按国内外域名分类。
- 同一域名首次连接成功后固定线路，代理恢复或临时中断不自动切换出口；切换网络模式或重启应用后重新选择。
- 备用线路仅在发送网站请求内容前尝试，不能重放已发送的表单或其他请求。仅代理模式仍禁止直连回退。

- **实际线路显示为全局约束**：自动选择模式下，浏览器必须按当前网站主域名实际成功建立连接所使用的线路显示“代理”或“直连”，并配对应图标；以底层连接记录为依据，禁止只根据代理是否连接、网络模式、国内外域名分类或预计线路推断。
- 切换网站、重定向、前进/后退、切换浏览器标签及线路选择完成时，地址栏与线路标识必须同步更新，读取当前标签当前网站的实际记录，不得沿用上一网站或其他标签的标识。尚未确定线路显示“正在选择…”，未建立连接且访问失败显示“未连接”，不得伪报已使用代理或直连。
- 线路标识说明当前网站主域名的连接线路；第三方资源按各自域名选择线路，不得将主域名标识解释为页面全部资源统一走同一线路。代理恢复后已固定直连的网站继续显示“直连”。
- 修改路由或线路展示后，必须核验真实代理连接显示“代理”、直连显示“直连”，并交替切换两类网站和标签、检查前进/后退；代理连接状态变化不得单独触发错误标识。自动化测试与重启后的实际界面验收分别记录，不得以配置状态或测试通过代替实际线路验收。

### 对话同步与冲突处理（全局约束）

- 对话同步必须优先保护本机内容：同步前保存当前账号的加密本机快照及合并基线；网络失败、版本冲突、重启和账号切换不得丢失尚未同步的对话。启动时必须识别并恢复本机未同步内容，不得直接用云端快照替换。
- 保存使用版本校验。发生版本冲突时，读取云端最新版本，基于共同基线、本机内容和云端内容进行合并；不同会话或兼容字段的更新可以自动合并，消息仅在内容一致或构成兼容的前缀扩展时合并。禁止仅更新版本号后用本机旧快照强行覆盖云端，也禁止用云端版本覆盖本机未合并内容。
- 同一消息分叉、删除冲突或其他无法安全合并的变更必须停止覆盖，保留本机快照和必要基线，并明确提示“本机内容已保留，云端未被覆盖”。不得静默丢弃任一方的未合并数据、拼接不兼容消息或自动选择某一版本替换另一版本。对需用户处理的冲突必须提供明确说明。
- 合并重试必须有界；连续冲突不得无限重试。保存队列执行时读取最新本机状态，合并返回时保留等待期间产生的新修改；校验账号归属，不能将旧账号的响应或内容应用到新账号。同步结果应同步更新会话列表和内容，并保留未发送草稿与当前操作状态。
- 通知依据真实错误描述，不得把版本冲突直接归因于“其他设备”。同一未解决的同步问题使用持续状态并去重提示，后台重试、切换会话和重复保存不得反复堆叠通知；同步恢复后清除错误状态，后续新的独立问题才重新提示。
- 修改对话保存、缓存恢复、账号切换或合并逻辑后，必须验证：独立更新合并、消息分叉、删除冲突、重复版本冲突、网络失败、重启恢复未同步内容、账号切换期间的响应隔离及通知去重。自动化测试与实际会话切换验收分别记录，不得仅以请求成功认定数据完整。

### 断网重启恢复与单实例保护（全局约束）

- 离线保存、离线重启、恢复网络、再次重启必须构成完整可恢复链路。本机未同步消息必须可恢复；离线读取缓存不得将本机待同步内容误标为云端已确认基线。必须分别保留上次云端确认版本、合并基线和最新本机快照，联网后基于真实基线合并并进行版本校验，不能通过替换版本号跳过冲突。
- 对话缓存按账号隔离并加密，使用同目录临时文件写入后原子替换；不得直接截断覆盖唯一的有效缓存。加密不可用或本机写入失败必须明确报告，不能伪报保存成功或同步成功。缓存保留成功后再尝试云端同步，失败不得删除未同步快照。
- 离线启动可使用加密凭据缓存中与当前 token 对应、此前已验证的最小账号归属恢复本机对话，状态明确为离线；不得将缓存身份视为新的在线认证成功，也不得把旧账号身份绑定到新 token。服务端明确返回会话失效时，清除失效凭据，禁止使用缓存身份继续在线访问；账号切换必须继续隔离缓存、响应和同步任务。
- 恢复网络后，待同步内容须由有界重试继续处理；成功合并并确认保存后更新本机基线及缓存、清除同步错误和通知去重状态。无法安全合并时继续保留本机与云端未合并数据；同一未解决故障不得因后台重试、重启恢复或会话切换反复堆叠通知。
- 生产应用必须在初始化账号、浏览器、缓存和后台同步任务前取得与 userData 对应的单实例锁；未取得锁的重复启动进程立即退出并聚焦已有窗口，已最小化时先恢复。禁止两个生产实例共享同一份数据目录进行缓存写入或对话同步。隔离测试实例必须使用独立测试数据目录，不得绕过锁后访问生产数据。
- 修改启动、账号恢复、缓存写入、同步重试或进程生命周期后，必须验证断网保存 → 离线重启 → 联网合并同步 → 再次重启的数据完整性，覆盖云端新增及内容分叉、缓存写入失败、登录失效和账号切换；同时验证重复启动只保留一个生产实例、聚焦已有窗口及通知去重。记录模拟断网与真实桌面重启的验收范围，不能将模拟测试写成真实系统断网验收。

### 账号切换与退出登录的数据隔离（全局约束）

- 对话记录、本机加密缓存、云端版本与合并基线、待同步任务及通知状态必须按账号隔离。任何旧账号内容、待同步快照或异步响应均不得写入、合并到或展示为新账号的数据；不能仅凭当前全局账号变量决定已排队任务的归属。
- 切换账号或退出登录前，先停止并等待旧账号正在运行的对话请求结束，收拢旧账号保存队列，将最新本机内容可靠写入旧账号专属加密缓存；落盘失败须明确报告并停止账号切换，不能丢弃待同步内容。旧账号未同步内容保留，重新登录该账号后恢复，不能迁移为匿名或新账号的对话。
- 账号切换期间禁止新的对话保存、会话变更和发送操作，暂停旧账号后台同步重试。凭据变更后立即使旧任务失效；排队执行及每次异步返回、重试和合并应用前，必须校验原始账号与账号会话世代。即使前后登录相同账号，旧 token 或旧世代的返回结果也不得覆盖新登录状态。
- 请求发送时绑定原始账号凭据；禁止旧任务改用新账号 token 发起保存或冲突重试。新 token 不得绑定旧账号已缓存的身份信息。退出后清除当前内存对话归属及界面引用，避免旧会话选择、加载或模型准备的延迟结果重新激活旧账号内容。
- 同步成功、失败、冲突和恢复事件必须携带账号归属；界面仅接受当前账号对应的结果。切换或退出时清除旧账号的通知状态并使旧界面请求失效，旧请求迟到的成功、错误或重试不得改变新账号的对话状态、弹出通知或清除新账号提示；通知去重状态不得跨账号共用。
- 修改账号登录/退出、对话保存、恢复、任务队列或通知逻辑后，必须使用隔离账号验证：A 未同步内容 → 切换 B 仅见 B → 退出后旧任务失效 → 返回 A 恢复其待同步内容；覆盖旧 GET/PUT 延迟返回、旧会话选择和发送准备、同账号重新登录 token 变化、旧通知迟到及落盘失败。真实账号操作与模拟测试分别记录，禁止为验收混用用户数据。

- 详情页分区标题与正文/标签列表之间统一保留 12px，使用容器 gap 单独控制；标题 margin 为 0，禁止被通用详情标题的 24px margin 覆盖或叠加。运行时“支持的模型”分区遵循此约束。
- 运行时导航在同一账号、同一环境下复用已渲染列表，60 秒内切回不重新请求或显示加载屏；超过 60 秒可后台刷新，已有内容保持可见。仅首次进入或切换账号/环境无匹配缓存时显示加载态。安装、卸载、登录、退出登录等明确变更立即刷新，不受导航缓存限制；支持的模型统一写入 RUNTIME_CATALOG 硬编码目录；实时查询仅用于开发核对清单，运行时列表、详情和模型选择不得在导航时启动 Codex 获取模型。缓存和页面内容不得跨账号/环境复用。

- 所有弹窗表单字段标题（原生 label、自定义字段标题及 Web Awesome form-control-label）统一为 12px、500 字重、1.6 行高、正文色，字段标题至控件间距 8px。不得因使用不同控件而出现字号、字重或颜色不一致。
- 表单折叠标题使用 `.form-disclosure`：图标 14px、图标与文字间距 4px，垂直居中，按钮本身及内部不额外增加左右 padding/margin；折叠图标左边缘与其他字段标题、输入框左边缘对齐。不要同时使用 start 插槽留白与 label gap，造成双重图文间距。普通操作按钮仍遵循既有 6px 图文间距。

- 对话助手消息统一按 GFM Markdown 渲染，支持表格、标题、列表、引用、代码块、强调和链接；流式输出及历史恢复使用相同渲染器。必须保留原始 Markdown 用于缓存与同步，不能保存渲染后的 textContent 导致格式丢失。HTML 经 DOMPurify 白名单过滤，禁脚本/事件/危险链接；来源链接仅允许 HTTP(S)，通过内置浏览器打开。
- Codex 对话使用 app-server 的 item/agentMessage/delta 立即推送文本增量，完成事件只补齐未发送部分，不重复整段输出；保留 thread/resume、取消清理、只读 sandbox、工具禁用及原对话线路隔离。旧 exec JSON 适配器保留兼容测试，不用于当前对话入口。

## 品牌与兼容性

项目品牌、窗口标题、登录界面及返回页统一为 **Kuneco**；项目目录名为 `Kuneco`，npm 包名为 `kuneco`，Go 模块为 `kuneco/backend`。

为保持现有账号、加密凭据、浏览器数据、会话和容器可用，保留旧用户数据目录 `定途工作空间` 与既有 `dingtu` 容器/卷/协议标识；这些是内部兼容标识，不作为界面品牌。macOS 凭据密钥在旧身份下初始化后，应用显示名切换为 Kuneco。旧项目路径可保留为指向新目录的兼容符号链接，供现有引擎进程和已保存路径继续使用。历史日志及截图保留原始内容。直接使用 Electron 开发运行时，macOS 原生菜单栏仍可能显示 Electron；应用窗口标题为 Kuneco。
